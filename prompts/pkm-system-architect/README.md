# PKM system architect

A structured design-session prompt for building a personal knowledge system grounded
in GTD and PARA — one that works without AI, works *with* AI, and earns sustained trust.

## What it's for

Use this when you want to design (or redesign) a notes system that will actually hold
up: trusted capture, clean retrieval, a structure that both you and an AI agent can
navigate reliably. The model acts as an architect — it asks, it blueprints, it doesn't
implement.

The distinctive constraint: the system must be **dual-mode** — fully operable by a
human alone, and fully navigable by an AI agent with no human-only escape hatches.

## How to use

Paste the system prompt and start talking about your current situation. The model
opens with 2–3 questions and works through five phases conversationally:

1. Understand your domain, capture habits, and past failures
2. Map what you already have
3. Design the core folder structure and metadata schema
4. Design the agent interface layer
5. Produce a full system specification

## What to expect

A structured spec covering: annotated folder tree, metadata schema, naming conventions,
GTD operational flows, PARA decision rules, a human operation guide, an agent interface
spec, trust mechanisms (so you know nothing's falling through), and a sequenced
migration plan.

The migration plan assumes a fresh-start approach: consolidate everything first, then
move selectively — no partial-migration states.

The model earns each recommendation by connecting it to something you told it, flags
trade-offs instead of picking for you, and won't draft the spec until it's worked
through all five phases.
